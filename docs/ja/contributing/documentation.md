# ドキュメント

ドキュメントへの貢献の方法はシンプルです。
ファイルは <https://github.com/pieceofcake2/docs> の `2.x` ブランチにホストされています。
自由にリポジトリをフォークして、変更・改善・翻訳を追加し、`2.x` ブランチに対して
Pull Request を作成してください。
またファイルをダウンロードせず、各ページの下部にある "Edit this page on GitHub" リンクから
GitHub のオンラインエディタを使って直接ドキュメントを編集することもできます。

ドキュメントは英語と日本語の Markdown で書かれ、[VitePress](https://vitepress.dev) でビルドされます。
テーマは [pieceofcake2/docs-skeleton](https://github.com/pieceofcake2/docs-skeleton) にあり、
ビルド時にクローンされます。すべての `pieceofcake2/*` リポジトリに適用される Organization の
貢献ガイドは [CONTRIBUTING.md (英語)](https://github.com/pieceofcake2/.github/blob/master/CONTRIBUTING.md)
です。このページでは、このドキュメントの編集方法を説明します。

<a id="local-development"></a>

## ローカルでの開発

```bash
./bin/dev-server.sh
```

このスクリプトはスケルトンを `.temp` にクローンし、`docs/`、`config.js`、目次のファイルを同期して、
http://localhost:5173 で VitePress の開発サーバーを起動します。
`git`、`node`、`npm`、`rsync` が必要です。

`2.x` ブランチへのプッシュは、`.github/workflows/deploy.yml` によって GitHub Pages にデプロイされます。

<a id="repository-layout"></a>

## リポジトリの構成

- `docs/en/` には英語のページ、`docs/ja/` には日本語のページがあります。両方のフォルダーの構成は
  同じで、`docs/en/foo/bar.md` のページの翻訳は `docs/ja/foo/bar.md` にあります。
- `toc_en.json` と `toc_ja.json` は各言語のサイドバーを定義します。ページを追加したときは、
  両方のファイルに追加してください。
- `config.js` には、ナビゲーションバーやバージョンのバナーなど、サイトの設定があります。

英語のページはサイトのルート (`/docs/installation.html`) から、日本語のページは `/ja/`
(`/docs/ja/installation.html`) から配信されます。

<a id="editing-guidelines"></a>

## 編集のガイドライン

- ページは現在の状態を説明するように書いてください。「フォーク固有」の別ページや
  注意書きは追加せず、元のページを編集してください。
- 本文と例には、モダンなディレクトリ構成 (`src/`、`templates/`、`config/`、`bin/cake`)
  を使ってください。従来の `app/` 構成には、役に立つ場合だけ触れてください。
- PHP のコード例は [コーディング規約](cakephp-coding-conventions) (CakePHP 5 の codesniffer)
  に従います。移行ガイドの「変更前」のように、意図的に古いコードを示す例は例外です。
- 移行するユーザーが知っておく必要のある点でフォークの動作が元の CakePHP 2.10.24 と異なる場合は、
  短い変更の注記を追加してください ([フォークでの変更の注記](#change-notes-for-the-fork) を参照)。
- `docs/en` と `docs/ja` の両方を更新し、変更を
  `docs/*/appendices/changes-from-the-original-book.md` に追加してください。

<a id="translations"></a>

## 翻訳

ドキュメントは英語と日本語でメンテナンスしています。英語版が正式な版です。英語のページを
変更したときは、できれば日本語のページも更新してください。難しい場合は、翻訳の更新が
まだ必要なことを Pull Request に書いてください。

- 内容とタイトルは同時に翻訳し、部分的な翻訳は送らないでください。
- 修正を送る前に英語のページと比較し、まだ翻訳されていない英語の変更も含めてください。
- ページ間のリンクが両方の言語で機能するように、ページの構成、コード例、アンカーは
  英語のページと同じにしてください。
- その言語の既存のページと同じ用語を使ってください。日本語のページは、です・ます調で書きます。
- アクセント付きの文字に HTML エンティティを使わないでください。ページは UTF-8 です。
- 元の内容に情報が足りない場合は、先に英語のページの修正を送ってください。

<a id="formatting-guide"></a>

## フォーマットガイド

ページは、いくつかの VitePress の拡張を加えた普通の Markdown です。例は既存のページを
参照してください。

<a id="line-length"></a>

### 行の長さ

本文の行は 80 桁程度で折り返してください。長い URL、表、コード例は例外です。

<a id="headings"></a>

### 見出し

各ページは、ページのタイトルである `#` の見出し 1 つで始めます。セクションには `##`、
サブセクションには `###`、その下には `####` を使い、各見出しの前後に空行を入れてください。

VitePress は見出しのテキストからアンカーを生成します。例えば `## Running Tests` には
`#running-tests` というアンカーが付きます。日本語の見出しからは同じアンカーができないため、
日本語のページで英語のページと同じアンカーが必要なときは、見出しの前に明示的に追加してください。

```md
<a id="running-tests"></a>

## テストの実行
```

<a id="inline-markup"></a>

### インラインマークアップ

- 強調 (イタリック) には `*text*`、強い強調 (太字) には `**text**` を使います。
  太字は控えめに使ってください。
- コードにはバッククォートを使います。メソッドや関数の名前 (`()` を付けます)、クラス名、
  オプション名、テーブルのカラム、ファイル名とパスが対象です。例えば `PagesController`、
  `find()`、`config/core.php` のように書きます。

<a id="lists"></a>

### リスト

順序なしリストの項目は `-` と空白で始めます。番号付きリストには `1.`、`2.` などを使います。
入れ子のリストと継続行は 2 つの空白でインデントします (番号付きリストでは 3 つ)。

<a id="links"></a>

### リンク

ドキュメントの他のページへのリンクでは、拡張子 `.md` を省略します。現在のページからの相対パスか、
その言語のルートからの絶対パスを使ってください。絶対パスは、英語のページでは `/`、
日本語のページでは `/ja/` で始めます。セクションにリンクするには、見出しのアンカーを追加します。

```md
[Controllers](../controllers)
[Testing](/development/testing#running-tests)
[テスト](/ja/development/testing)
```

<a id="describing-classes-and-their-contents"></a>

### クラスとその内容の説明

クラスやメソッド用の特別なディレクティブはありません。クラスとそのメソッドは次の形式の行に
説明を続けて記述し、本文中では `Cache::read()` のようにバッククォートで参照してください。

```md
`class` **Cache**

`static` Cache::**read**($key, $config = 'default')
```

<a id="source-code"></a>

### ソースコード

コード例は、言語名を付けたフェンス付きのコードブロックで書きます。PHP のコードには `php`、
シェルのコマンドには `bash`、出力やハイライトしないものには `text` を使います。読者の役に立つ
場合は、PHP のコード例をファイル名のコメントで始め、モダンなアプリケーションの構成を使ってください。
例えば `// src/Controller/PostsController.php` のように書きます。異なるツールでの同じコマンドの
ような選択肢は、`::: code-group` コンテナでまとめられます。

PHP のコード例はコーディング規約に従います。コード例を確認するには、ファイルに保存し
(必要なら `<?php` を追加し、断片はクラスやメソッドで囲みます)、`cakephp/cakephp-codesniffer`
^5 をインストールしたプロジェクトから `vendor/bin/phpcs --standard=CakePHP` を実行してください。
CakePHP のルールセットは `/tmp/` を含むパスをスキップするため、`tmp` ディレクトリの下には
保存しないでください。ファイルコメントや名前空間がないなど、断片には適用できないスニフは無視してください。

<a id="alerts-and-containers"></a>

### アラートとコンテナ

ヒント、注意、警告には GitHub 形式のアラートを使い、完全な文で書いてください。

```md
> [!TIP]
> 忘れがちな役に立つ情報。

> [!NOTE]
> 特に重要な情報。

> [!WARNING]
> つまずきやすい点や、セキュリティについての情報。
```

CakePHP 2 で機能が追加、変更、非推奨になったバージョンを示すには、タイトル付きの `info`
コンテナを使います。`tip`、`warning`、`danger` のコンテナも同じ方法で独自のタイトルを付けられます。

```md
::: info Added in version 2.6.3
この素晴らしい機能はバージョン 2.6.3 で追加されました
:::
```

<a id="change-notes-for-the-fork"></a>

### フォークでの変更の注記

削除された機能、変更されたデフォルト値、変更されたメソッドのシグネチャなど、アプリケーションを
移行する読者が知っておく必要のある点でフォークの動作が元の CakePHP 2.10.24 と異なる場合は、
対象の本文の隣に `pieceofcake2` コンテナで短い注記を追加してください。

```md
::: pieceofcake2
Xcache と Wincache のエンジンは削除されました。
:::
```

デフォルトのタイトルは "Piece of Cake 2 fork" です。別のタイトルは、`::: pieceofcake2 Cache engines`
のようにコンテナ名の後に指定します。注記は 1 文から 3 文にしてください。現在のパスやコマンドを
含め、それ以外の内容はページの通常の本文に書きます。

<a id="including-other-files"></a>

### 他のファイルの取り込み

VitePress の `@include` ディレクティブを HTML コメントとして書くと、ページに他の Markdown ファイルの
一部を取り込めます。例は `docs/ja/core-libraries.md` を参照してください。`{28,97}` のように
ファイル名の後に波かっこで行の範囲を指定すると、その行だけを取り込みます。他のページに
取り込まれているファイルを編集したときは、リポジトリで `@include` を検索し、取り込む側の
ファイルの行の範囲が引き続き同じセクションを選択しているか確認してください。
